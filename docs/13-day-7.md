# Day 7 — deterministic next-action decisions

Track A now chooses an explainable instructional plan independently from activity generation. It reads the enrolled published graph and stored learner state, pins approved policies and compatible catalog versions, preserves whole-task context and fits complete activities into a requested time budget.

## API walkthrough

Authenticate with the learner's `X-API-Key`, register/enroll using Day 5's APIs, and use exact approved policy UUIDs from Day 6. Request:

```http
POST /api/v1/learners/{learner_id}/loop-plans
Content-Type: application/json
X-API-Key: <learner credential>

{
  "enrollment_id": "<own enrollment UUID>",
  "target_skill_id": "<skill UUID in enrolled domain>",
  "learning_science_policy_id": "<approved learning-science policy UUID>",
  "safety_policy_id": "<approved safety policy UUID>",
  "time_budget_minutes": 25
}
```

First creation returns 201 and Location; identical versioned input returns the saved representation with 200. Read through `GET /api/v1/loop-plans/{plan_id}`. The response includes a complete replayable input snapshot and a decision with ordered, catalog-linked steps. Plans never generate content, score attempts or update state. Budget failure returns 409 with the minimum required duration; missing compatible approved catalog coverage also returns 409. Foreign learner/enrollment/target IDs return 404. Plan reads remain available after course archival, while new planning is blocked.

## Deterministic rule version `track-a-v1`

1. Validate an acyclic graph and complete one-state-per-skill coverage. Find all transitive prerequisites of the requested target. Ignore unrelated gaps. Walk prerequisite-first topological order, breaking ties by code then ID, and select the earliest prerequisite whose band is not secure; otherwise select the target.
2. Unknown focus means diagnosis or guided work with high support and introductory complexity. Developing focus retains high support. Secure focus fades support and uses standard complexity. These are provisional rules, not calibrated mastery thresholds.
3. High support starts with a whole-task worked example and ends with a constructed whole-task return. Include supportive information for non-routine reasoning and procedural information for routine focus aspects. All steps share the decision's target/context key; the focus skill is explicit for generation and later evidence alignment.
4. Optional selected-response part-task practice is eligible only for observed developing performance on a routine focus requiring automaticity. Insert it between context and return only if it fits the budget. Unknown knowledge alone does not justify automaticity practice. A non-routine focus never gets part-task practice.
5. Secure focus receives a constructed whole task with minimal support. Secure does not award certification or end the loop automatically. Constructed responses remain subject to instructor review before authoritative scoring.
6. Only approved activity versions matching both exact policy UUIDs and required component mappings are candidates. Choose the shortest full duration, then code, version and UUID. No automatic latest-version assumption or duration truncation occurs. Reserve the whole-task return before adding optional practice.

The input hash includes the planner version, graph, all enrollment skill bands/counts/revisions, exact policy metadata, approved compatible candidates, target and budget. Collections are canonicalized, so database/list ordering does not change the decision. Identical inputs give identical decision content and reuse one saved plan per enrollment. New approved candidates can change the fingerprint even if the chosen sequence stays the same. A saved GET always returns its frozen snapshot.

## Acceptance fixtures

The five-skill synthetic chain is VARIABLES → EXPRESSIONS → CONDITIONALS → LOOPS → DEBUGGING. Fixtures use stable UUIDs and reviewed synthetic catalog metadata. The internal observed bands require positive evidence count and revision; they are illustrative test inputs without actual evidence events.

| Fixture at 25 minutes | Focus / action | Support / complexity | Sequence | Estimated minutes |
|---|---|---|---|---|
| Unknown | VARIABLES / diagnostic or guided | High / introductory | Worked context → whole-task return | 16 |
| Beginner: developing VARIABLES | VARIABLES / guided practice | High / introductory | Worked context → routine automaticity practice → whole-task return | 19 |
| Experienced: secure fixture bands | DEBUGGING / independent task | Minimal / standard | Constructed whole task | 10 |

A beginner budget of 16 omits optional practice and preserves both whole-task steps. An unknown budget below 16 or experienced budget below 10 is rejected. Catalog durations are estimates, not an assurance of individual completion time.

Stored learner states remain `unknown`, zero evidence and revision zero under migration 0005's original constraint. The public planning API therefore demonstrates unknown-state planning today. Beginner/experienced behavior is verified through the same pure decision function with internal fixtures; clients cannot submit bands or write proficiency to bypass evidence. Day 9 records approved evidence provenance; Day 10 must apply evidence to state before these behaviors become available for persisted learners.
