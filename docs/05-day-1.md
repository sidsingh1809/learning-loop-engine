# Day 1 walkthrough

## Objective

Understand the project boundary and demonstrate the first complete request path: API request → validation and authentication → MySQL write → JSON response → subsequent read. This teaches the foundation used by every later feature.

## Run and inspect

From the project directory, start Docker Desktop and run:

```bash
python3 scripts/init_local_env.py
docker compose up --build -d --wait api
docker compose exec api python --version
```

Expected interpreter: `Python 3.9.21`. The local host Python can differ; application execution is inside the pinned container.

Open <http://localhost:8000/docs>. In a local editor, find `API_KEY` in `.env`, use **Authorize**, and submit this example to `POST /api/v1/courses`:

```json
{
  "code": "CS101",
  "title": "Synthetic introductory programming pilot",
  "description": "Local demonstration data, not a university-approved course."
}
```

Expected: 201, a generated ID, normalized code, UTC creation time, and Location header. Use that ID with `GET /api/v1/courses/{course_id}`. Listing courses returns an `items` array plus pagination values. Repeating creation of the same course code returns 409 rather than inserting a duplicate.

The same demonstration is automated:

```bash
python3 scripts/demo_day1.py
```

The script only uses HTTP endpoints for application data. Repeated runs safely reuse its existing course code. It reads the local key without printing it.

## Read the code in request order

1. `app/main.py`: mounts the course router under `/api/v1`, declares health checks, and sanitizes database errors.
2. `app/security.py`: validates the development integration key before course access.
3. `app/schemas.py`: validates input, rejects unknown fields, normalizes the code, and defines the returned JSON shape.
4. `app/courses.py`: handles course creation, duplicate-code conflicts, lists and detail reads.
5. `app/database.py`: supplies a database session per request and closes it afterward.
6. `app/models.py`: defines the Python representation of the course row.
7. `migrations/versions/0001_courses.py`: creates the actual MySQL table through Alembic.

A migration changes database structure. An API request changes application data. Keeping them separate lets deployment tools manage schema versions while external applications interact only through the API.

## Verify

```bash
docker compose --profile test run --build --rm tests
```

This runs contract tests plus integration tests on the disposable `learning_loop_test` database. It exercises migration upgrade/downgrade/re-upgrade, model/schema agreement, UTF-8 content, API persistence, duplicate rejection, pagination, validation and missing records. It does not delete the application database.

For fast host-only checks after installing dependencies:

```bash
.venv/bin/python -m pytest -q -m 'not mysql'
```

These checks do not establish MySQL compatibility or exact Python 3.9.21 execution. Use the container suite for those claims.

## Common setup issues

- Cannot connect to Docker: start Docker Desktop and wait for the engine to become ready.
- Port 8000 or 3307 is in use: stop the conflicting local service or change the relevant host binding and client URL consistently.
- API returns 401: use the generated `.env` key in `X-API-Key`; health checks are public but course routes are protected.
- Course creation returns 409: that normalized code exists; retrieve it or use another unique code.
- Database password changed after first startup: MySQL initialization variables only apply to a new data directory. Restore the original local credentials or perform an explicit database password rotation; do not delete the data volume as a routine fix.
- Code changes do not appear: rebuild with `docker compose up --build -d --wait api`.

## What Day 1 does not establish

No adaptive recommendations, generated activities, learner data, or mastery inference exist yet. The API key is a local development mechanism. We have not tested educational effectiveness. Day 2 adds course lifecycle operations and defines the actor/role boundary before introducing learner records.
