# Day 2: course lifecycle and access boundary

Day 2 adds course editing, archival, author ownership and development principals. It also defines the API conventions and the university identity integration boundary. Domain graphs and the adaptive loop start in later sessions.

## Run the acceptance demo

```bash
python3 scripts/init_local_env.py
docker compose up --build -d --wait api
docker compose --profile test run --build --rm tests
python3 scripts/demo_day2.py
```

The setup script preserves existing credentials and adds `DEV_PRINCIPALS` only when that setting is absent. A deliberately configured empty list stays empty; configure a learner credential before running the role demo. Keys remain in `.env`; do not copy them into reports.

The existing `API_KEY` identifies `dev-author`. Existing Day 1 courses belong to this author after migration. The generated additional credentials identify `dev-instructor`, `dev-learner`, and `dev-integration`. The server resolves identity from the key; sending a role or subject header does not grant permission.

The demo creates one fresh synthetic course through HTTP, edits its title, verifies that the learner cannot edit or archive it, archives it twice, reads the retained record, and verifies that edits, hard deletion, and code reuse are blocked. Every run leaves one archived synthetic course. It does not edit the original CS101 pilot.

## Try it in Swagger

Open <http://localhost:8000/docs> and authorize using the local `API_KEY`.

1. Create a course with a fresh code using `POST /api/v1/courses`.
2. Copy its `id`; submit `{"title":"Revised synthetic course"}` to `PATCH /api/v1/courses/{course_id}`. Omitted fields stay unchanged.
3. Call `POST /api/v1/courses/{course_id}/archive`. It returns the retained course with `status: archived` and a UTC `archived_at`.
4. Read it by ID, or list with `status=archived` or `status=all`. The default list is active courses only.
5. Repeat archive: the same representation is returned. Try editing it: expect 409.
6. Switch authorization to the generated learner key; course reads succeed, writes return 403.

## Trace the implementation

Follow `app/security.py` → `app/identity.py` → `app/courses.py` → `app/schemas.py` → `app/models.py`. Authentication establishes a principal; authorization requires both the author role and matching course ownership. The PATCH and archive transactions lock the course row so they cannot race past each other.

Migration `0002_course_lifecycle` adds `created_by`, `updated_at`, and `archived_at`. It backfills ownership to `dev-author` and the update time to the original creation time. Migration 0001 is preserved. Downgrading 0002 keeps course rows but discards lifecycle and ownership metadata; use downgrades only for disposable verification, not as a routine application rollback.

Read [the API contract](07-api-contract.md) and [identity design](08-identity-design.md), then inspect the lifecycle and migration tests in `tests/test_mysql.py`. Contract tests cover rejected payloads and role spoofing without needing a database.
